# osu!mania 投皮处理规范

处理用户提到“投”“投皮”“投的长度”“投 50px”“球皮”“菱形皮”“渐变皮”时，必须先读取本文件。不要把这些说法泛化为“Mania 长度”。

工具用途：`mania-throw-length` 只修改 Hold Body PNG 顶部连续透明行数；它不是普通缩放工具，也不修改 `skin.ini`。修改投的长度前，先从目标 `[Mania]` 段解析出实际 `NoteImage#L` PNG。运行 `osu-skin mania-throw-length "<投皮 PNG>" --throw-length <px> --output "<输出 PNG>" --dry-run --json` 检查计划；确认后移除 `--dry-run` 执行写入。不要把皮肤目录直接传给该命令。完整工具选择见 `tools.md`。

## 1. 术语优先级

按以下领域语义理解用户请求：

| 用户说法 | 默认含义 | 不得默认解释为 |
|---|---|---|
| `投`、`投皮` | osu!mania 长按音符持续显示的身体图（Hold Body） | 普通 note、长按头、长按尾、谱面 hold duration |
| `投的长度`、`投 50px` | 投皮图片顶部纯透明区域的高度；`50px` 即顶部 50 行完全透明 | `skin.ini` 中的长度数值、判定线高度、舞台高度、谱面时值 |
| `投皮头`、`顶端` | 透明区之后、身体最上方的 cap | Note Head 文件 |
| `球皮` | 半圆形 cap 的投皮 | 圆形普通 note |
| `菱形皮` | 半菱形/尖顶 cap 的投皮 | 菱形普通 note |
| `渐变皮` | cap 区使用透明度渐变的投皮 | 整张图片任意渐变 |
| `留白` | 图片左右两侧等宽透明边距，贯穿全图 | 顶部透明区或底部空白 |

用户只说“把投改成 50px”时，优先解释为“把投皮图片顶部透明区改成 50px”。如果用户提供的上下文明显不是投皮生成或图片修改，再简短确认实际对象。

## 2. 生成器约定与已有皮肤映射

本项目的投皮生成器约定：

- 唯一生成目标是 `mania-noteNL.png` 这一类 Hold Body 图片，`N` 表示实际编号，例如数据库默认资源 `mania-note1L.png`；
- 该类文件表示 Hold Body / 投皮，并对应数据库的 `NoteImage#L`；
- 不生成 Note Head，也不生成 Note Tail；
- 图片名可以由用户指定，但语义仍是投皮。

编辑已有皮肤时仍必须核对实际 path，不要只凭文件名猜测：

1. 定位正确 `Keys: N` 的 `[Mania]` 段；
2. 读取该段实际的 `NoteImage#H`、`NoteImage#L`、`NoteImage#T` 路径；
3. 检查这些路径对应的真实图片、尺寸和透明结构，并对照用户文字描述的症状；
4. 明确告诉用户本次把哪个 path/file 当作投皮，以及依据；
5. 证据不足时询问用户补充路径、文件或 keycount，不强行重命名或覆盖。

数据库的标准映射是 `H=长按头`、`L=长按体/投皮`、`T=长按尾`。生成新投皮和修改标准 `[Mania]` 段时使用 `NoteImage#L`；如果目标皮肤把该字段指向自定义文件，沿用该 path 并报告。

## 3. 投皮面尾识别

用户在 Mania 中说“尾”“面尾”“后面尾”或“收尾”时，口语描述的是屏幕上的位置，不一定是数据库语义的 Hold Tail。没有皮肤文件时，先索要皮肤目录、`.osk`/zip 或至少 `skin.ini` 与 H/L/T 图片和 keycount；不要先给尺寸、翻转或 `NoteBodyStyle` 修改建议。

取得文件后：

1. 运行 `osu-skin mania-analyze "<皮肤目录>" --keys <N> --client lazer --dependencies --json`，解析有效 `NoteBodyStyle` 与实际 H/L/T 文件，包括 fallback、SD/`@2x` 和动画。
2. 对实际 `NoteImage#T` 运行 `osu-skin image-inspect "<T 图片>" --transparent-rows --json`。
3. 当输出的 `alpha.max == 0`，或 `alpha.transparent == width * height` 时，T 为全透明。这是把画面上的面尾判定为投皮收尾的决定性文件证据：保持 T 全透明，可见面尾由 `NoteImage#L` 的 cap 承担。
4. 当 T 存在任何可见像素时，它是普通 Hold Tail；转到 `lazer-image-scaling.md` 检查 T 的普通 note 尺寸、Y 翻转和 flip，不把它误判为投皮 cap。

绝大多数投皮按顶部叠加设计。lazer 中 `NoteBodyStyle: 0` 使用拉伸，非 `0` 值统一进入 lazer 独立实现的重复/填充分支，呈现类似从顶部叠加的效果。修复投皮面尾时检查实际 `NoteImage#L` 的宽度、高度、顶部 cap 和重复接缝；不要按内部枚举名盲试多个非 `0` 值，也不要为了修投皮而把全透明 T 换成可见尾图。

确认是 lazer 投皮面尾变形后，修复对象是实际 `NoteImage#L`，并先运行：

```powershell
osu-skin mania-lazer-hold-body-fix "<NoteImage#L 图片>" --column-width <该列 ColumnWidth> --output "<输出 PNG>" --dry-run --json
```

确认计划后移除 `--dry-run` 执行。命令算法是：

1. 目标宽度为 `round(ColumnWidth * 1.6)`，目标高度为 `32800`；
2. 按目标宽度对输入原图等比缩放，高度随比例变化；
3. 缩放后高度大于 32800 时保留顶部并裁剪底部；
4. 缩放后高度小于 32800 时，取输入原图底部最多 1000 行，按相同比例缩放后循环平铺到 32800；
5. 保存最终目标尺寸的 L 图。

该命令修复的是 lazer 因素材尺寸不匹配造成的拉伸；如果原 PNG 的目标外观已经依赖 stable 客户端的拉伸，命令不能还原 stable 的未拉伸原稿，也不能自动完成这种适配。`NoteImage#T` 全透明的约束仍然保留，SD/`@2x` 是否使用要依据 `mania-analyze` 结果处理。

## 4. 图片结构

投皮画布从上到下依次为：顶部透明区、cap、body；左右为贯穿全图的对称透明边距。

```text
图片总高
┌──────────────────────────┐
│       顶部纯透明区        │  投的长度（Throw Length）
├────┬──────────────┬──────┤
│透明│     Cap      │ 透明 │  球形/菱形/矩形/渐变顶端
│边距├──────────────┤边距  │
│    │     Body     │      │  填充和可选边框延伸到底部
│    │      ...     │      │
└────┴──────────────┴──────┘  底部不得额外留白
```

生成和修改时遵守：

- 默认图片宽度为 `40px`，除非用户指定其他宽度；
- 左右 margin 数值相同，内容宽度为 `image_width - 2 * margin`；
- margin 从第一行贯穿到最后一行；
- 投的长度是从图片顶部开始连续、整行 alpha=0 的行数；
- cap 紧接顶部透明区；
- body 紧接 cap 并一直延伸到图片最后一行；
- 不在底部添加透明行；
- 顶部透明区、左右 margin 的 RGB 不重要于可见效果，但应避免透明 RGB 污染导致缩放白边。

## 5. 生成参数

从用户请求中提取并确认以下参数。用户未指定时只对低风险视觉参数采用默认值；会改变输出文件映射的参数必须确认。

| 参数 | 含义 | 默认/约束 |
|---|---|---|
| image width | 整张图宽度 | 默认 40px，必须大于 `2 * margin` |
| image height | 整张图高度 | 防重复目标通常为 32800px |
| output name | 输出文件名 | 使用 `mania-noteNL.png` 形式或用户指定名称；`N` 是实际编号，已有皮肤沿用 `NoteImage#L` path |
| side margin | 左右各自透明像素 | 左右相等、非负 |
| throw length | 顶部纯透明行数 | 非负；必须小于图片高度 |
| cap shape | 球形、菱形、矩形、渐变或用户素材 | cap 位于 throw length 之后 |
| cap height | cap 垂直高度 | 与形状和内容宽度协调 |
| fill | Body RGBA | 可以半透明 |
| border | Body 边框 RGBA/宽度 | 可关闭；不能侵入 margin |
| opacity | 所有非透明内容的整体透明度 | 0-100% |

常见预设仅表示参数组合，不是另一种文件类型：

- 球皮：半圆 cap + body，可带细边框；
- 菱形皮：尖顶/半菱形 cap + body；
- 矩形皮/纯色皮：水平顶端 + body；
- 渐变皮：cap 区按约定改变 alpha，再接 body。

## 6. 修改“投的长度”

对已有投皮图片执行以下逻辑：

1. 把图片顶部连续整行 alpha=0 的行数记为 `current`。
2. 当 `target > current` 时，将整张原图内容向下移动 `target - current` 行，在顶部增加透明行；超出画布底部的内容被裁掉。
3. 当 `target < current` 时，将整张原图内容向上移动 `current - target` 行，移除对应数量的原顶部透明行。
4. 保持图片宽高不变。向上移动产生的底部空缺，使用变换前原图最后 1000 行从第一行开始循环填充；原图不足 1000 行时使用原图全部行。
5. 当 `target = current` 时保留全部像素不变。
6. 拒绝全透明图片、非 PNG、负数目标以及大于等于图片高度的目标。
7. 输出到新文件或用户确认的目标；不要修改 `skin.ini` 数值，因为投的长度由 PNG 顶部透明行决定。

## 7. 验证清单

生成或修改后逐项验证并报告数值：

- PNG 可解码，宽高等于目标值；
- 存在 alpha 通道；
- 顶部恰有目标数量的连续全透明行；
- 第 `throw_length + 1` 行进入 cap/可见内容（允许形状角落透明，但该行不能整行透明）；
- 左右 margin 在全部行上都为全透明且宽度相等；
- 可见内容没有越过 margin；
- cap 后 body 连续；
- `target < current` 时，底部填充行数等于 `current - target`，来源是原图最后 1000 行且循环顺序正确；
- `target > current` 时，报告底部被裁掉的行数；
- alpha=0 附近没有明显白色 fringe 污染；
- 若用户反馈重复或拉伸，读取 `lazer-image-scaling.md` 后再判断图片高度和 `NoteBodyStyle`；
- 输出名与生成器约定或目标 `[Mania]` 的 `NoteImage#L` path 一致；SD/`@2x` 配对和逐列映射没有被遗漏。

没有在游戏客户端中实际验证时，只报告静态验证通过，不宣称游戏内效果一定正确。
